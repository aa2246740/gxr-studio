# 照片和个人信息

工作室只在你这台电脑上跑，不上传照片，也没有账号。

从文件头读进索引的是拍摄时间、镜头名、ISO、方向和尺寸（`meta.PhotoMeta`，`shots` 表）。不读 GPS。机身型号在解析结果里，不进索引表。

照片文件留在图库目录。删掉这个目录就是删掉工作室保存的照片和索引。应用数据目录里是相机数据、标定、LUT、界面偏好（`prefs.json`）和可选的 `flags.json`，删掉它不影响图库里的文件。`prefs.json` 的写入走 `PrivateDir`。

用户的 LUT 只在本机应用数据目录里保存。多文件和文件夹导入只收 cube，按原始字节的 SHA-256 去重并命名；名称、TITLE、分组、来源、作者、许可均作为数据。cube 导出位于 `luts/exports/`，保留署名与许可，TITLE 清理后再写入。生成的我的配方也在来源中保存署名，删除 LUT 后仍保留。所有库修改、导出和拟合作业的写入均用 `PrivateDir` 核对，不能写到 Git 工作区、图库或任何已登记的卡目录。照片自己的 LUT 选择沿用图库的编辑记录和位置核对。公开仓库不保存第三方 LUT，测试现场生成 cube。

文件头、数据行间和末尾的注释均保留。未改动的导出保留原文件字节；更改署名时不移除原注释，新增字段每一行仍为注释。原子替换时的临时文件从创建和写入开始就纳入失败清理。

## 相机配方文件和其他理光字节

r5 的 `GXRFX.BIN` 同样属于私有相机数据，只读导入、保存于应用数据目录。公开仓库的内容扫描同时拒绝库和目录容器的二进制魔数。

相机配方文件（`GXRCE.DAT`）、标定包，以及以后的备份和版本，只写进应用数据目录。写之前核对真实目标目录（`privacy.check_private_dir`）：不能在任何 Git 工作区里（逐级往上找 `.git`，经链接进入的也算），不能在卷根、卡、DCIM 或图库下面。不通过就拒绝，报"无法导出到这个文件夹。请选择其他文件夹。"，一个字节都不写。发现到的卡根（登记了写保护的目录）不管调用方有没有列出来，都算禁止的目的地。

真正写的时候用 `privacy.PrivateDir`：核对之后按真实路径从根逐级以"不跟随链接"的方式打开目录，之后的创建、读回、删除、改名和整体替换全部相对这个目录句柄进行，每次改动之前再核对一次句柄的真实路径。核对之后有人把目录换成指向卡的链接，也写不进去。每一次创建、写入、改名、读取和删除之前，核对的都是这次真正要用的那个父目录句柄（子目录在打开之后被整个移走也拦得住）。审计钩子按真实的 `dir_fd` 记录这些写入，相对路径的上下文保留的是目录句柄本身，事件发生时再解析；所有写入都按解析链接后的真实位置判断，经过别名写进卡里会被拦下，记录的也是卡上的真实位置。

HDR 版本（`.studio/hdr/`）只在电脑上生成，内容是你自己的照片加上一幅增益图，不含相机配方或标定数据。写之前先按真实路径核对 `.studio/hdr` 在图库里，再用 `privacy.PrivateDir` 打开，卡根一律禁止；`.studio/hdr` 被做成指到卡上的链接时一个字节都不写。

图库自己的写入（放照片、建日期文件夹、改时间、编辑记录、修复、暂存区、索引）同样按真实路径核对：图库里的文件夹被做成指到存储卡的链接时一律不写。启动时，拿锁、建 `.studio`、清临时目录、打开索引这些第一次写入之前，先只读找出插着的卡，核对图库根不在卡上、`.studio` 和其中会写的每个位置都还在图库里；不合格就不启动，并说明原因。

私有目录写入时，每次写字节之前和之后都核对实际的父目录句柄；写的过程中目录被移走，就把这个文件里已经写进去的字节清空（只动自己打开的文件，不再对移走的目录做删除等操作），错误信息里写明那里留下了一个 0 字节的文件。启动时也核对一次应用数据和导出目录，不通过只记日志（JPEG 导出不受影响）。

仓库这边另有两道：`.gitignore` 忽略相机配方文件、效果文件、备份和 `camera/`；`scripts/private_bytes.py` 按内容检查（文件开头的魔数、二进制里的魔数、长 hex/base64 解码后的魔数——按行换行的也认、已登记的 SHA-256，zip/tar 里的成员也查；压缩流的每一段、tar 结束之后的字节、zip 里没有成员占用的字节都单独检查；套得太深、太大、读不出来的归档算检查失败，并写明哪个成员没查），提交前检查暂存区里的 blob（按对象 id 读，不读工作区的文件），`make check` 检查整个工作区和 `uv build` 出的分发包。测试夹具一律在测试里现场生成（`tests/support/fake_card.py`）。

## 存储卡的身份

接口里的 `card_id` 是工作室每次发现挂载时随机生成的会话号，只在内存里，卡拔出、换卡、重新挂载或重启后作废。卷 UUID（`diskutil info -plist <挂载点>`，参数数组调用，超时 5 秒）只用来关联"这个卷上读过哪些文件"（`seen2` 表），不代表哪张物理卡。导入不会凭这些记录跳过读取，除非 `cards/coverage.py` 的 `SEEN_TRUST_UUID` 打开（默认关，要先证实 GXR 格式化后 UUID 一定会变）。

令牌只活在启动命令、cookie 和请求头里。日志要经过 `observe.redact`，不保留 Bearer、`token=` 查询和 GitHub 令牌形状。

可选的 Sentry（`GXR_STUDIO_SENTRY_DSN`）默认关闭。打开之后也只送打过码的失败任务事件：家目录、卷、卡路径和文件名换成占位符，不送照片、DNG、DAT 或令牌。详见 `docs/observability.md`。

这是给你自己用的本地工具，没有面向别人的数据采集，所以没有同意横幅或远程删除接口。
