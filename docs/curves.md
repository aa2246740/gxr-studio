# 主曲线与红绿蓝曲线

「调整」里的曲线只在电脑上生效。选择「主曲线」「红」「绿」「蓝」，在图中点按增加点，拖动调整，双击中间的点删除。圆点表示这个通道已经调整；其他已调通道的曲线淡显。两端的点保留。

「重置此通道」清除当前通道，「重置全部曲线」清除四条曲线。「调整」底部的「重置」同时清除滑块与全部曲线。保存、复制调整、撤销和重做都携带四个通道。

## 数据与颜色顺序

sidecar 的 `curve` 为 `null` 或包含 `master`、`r`、`g`、`b` 的对象。每个通道可缺省、为 `null`，或包含 2–16 个 `[x, y]` 点，范围为 0–255，横坐标严格递增。恒等曲线省略，全部恒等时省略整个对象。旧的 `{"master": [...]}` 不增加其他字段。

服务端用不可变的 `Curves` 表示这四个通道，浏览器的草稿和 GPU `Look.curve` 使用相同的对象形状。选择通道属于界面状态，不写入照片。相比保留单独的 `master` 字段再添加 RGB 旁路，这个模型让保存、缓存和撤销只处理一个字段。

曲线仍在原来的 0–255 显示编码域生效，使用原有的 PCHIP 插值、端点夹取和每码值四个采样点。顺序为画面对比／高光／阴影 → 单通道曲线 → 主曲线。单通道先、主曲线后，与 [GIMP 的 gimp_curve_map_pixels](https://github.com/GNOME/gimp/blob/master/app/core/gimpcurve-map.c) 相同。这里匹配组合顺序，插值算法和颜色链仍沿用 GXR Studio。

RAW 配方路径在配方链输出后、最终 8 位量化前查表。JPG 和 LUT 路径在 sRGB 编码与已有 8 位落地之后查表，后面仍是黑点、饱和度、自然饱和度、暗角与几何。没有把曲线移到线性光域，也没有添加曲线之间的中间量化。

仅主曲线或滑块调整使用原来的 1021 点一维表。有 RGB 曲线时合成三张 1021 点表；CPU 按通道查表，GPU 连续存放 R、G、B 表，仍在一次颜色 pass 中完成。恒等通道不创建插值器；全部恒等且滑块未调时不查表。

## 验证

`tests/test_rgb_curves.py` 检查参数、顺序和逐通道像素结果，并在本机实图上对照 0d3b08d 的旧 JPG 调整算法，比较像素和 JPEG 字节。GPU 的 RAW、JPG、显示类 LUT、Log LUT 组合在 `tests/test_gpu_parity.py` 使用原有门槛对拍。保存与复制撤销覆盖在 `test_paste_edits.py`、`test_paste_ui.py`；固定 Chromium 的真实拖动覆盖在 `test_rgb_curves_browser.py`。

`scripts/measure_curves.mjs` 在隔离实图实例上交错运行原版主曲线、新版主曲线和蓝曲线，每种五轮；第六轮单独采 CPU profile，不计入耗时。macOS 使用固定 Chromium 的 Metal 后端，记录实际适配器。脚本记录输入到 GPU 提交及 GPU 完成的时间、颜色 pass CPU 时间、帧数、rAF 间隔和错误，并核对读回图像包含实图颜色、定时区域内像素确实改变、保存通道正确。它接受原版 `web/` 的本地副本，原版 UI 和 GPU 引擎均从该副本加载；服务端与照片相同。每轮结果、最终 JSON、profile 和截图只写到调用者指定的本地目录，不上传照片。GPU 完成时间不代表屏幕实际呈现时间。
