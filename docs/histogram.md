# 直方图和溢出提示

大图（编辑器）右侧面板最上面、工具标签之上，所有标签（配方 / 调整 / 裁剪 / 边框 / 时间戳 / 信息）下都在。
前端代码：`web/assets/histogram.js`（面板、更新节奏、按键）、`histogram_math.js`（规则）、`histogram_draw.js`（画法）、
`histogram_sources.js`（数据来源）、`histogram.css`；显卡一侧：`frontend/src/shaders/hist.wgsl`、`present.wgsl`、`engine.ts`。

## 看什么

- 红、绿、蓝三块半透明的填充叠在一起，重叠处混色（红 + 绿 = 黄，绿 + 蓝 = 青，红 + 蓝 = 品红，三色都有就接近白）。一条细白线是亮度。
- 左边是暗部，右边是高光，256 档。纵向开方后画，让暗处少量的点也看得见；最左和最右两档常常是一根针（那一档堆了很多点），封顶在框里。
- **数的是导出时的样子**：配方、LUT、调整、曲线、几何（拉直、旋转、翻转、透视）、裁剪之后。**不含边框和时间戳**。
- 点标题收起 / 展开，记在浏览器里（`localStorage` 键 `gxr-studio.histogram-collapsed`，`1` = 收起）。收起后只剩一行：标题和两个三角，所以溢出提醒还在。

## 溢出（暗部死黑 / 高光死白）

| | 判定（对导出时的 8 位码值） | 画面上的颜色 |
|---|---|---|
| 暗部死黑 | 红、绿、蓝**三个都 ≤ 2** | 蓝 `rgb(40, 110, 255)` |
| 高光死白（过曝） | 红、绿、蓝**三个都 ≥ 253** | 红 `rgb(255, 50, 40)` |

- 留 2 级余量：JPEG 压缩和取整会让纯黑纯白差一两级，肉眼分不出。
- 只有一个颜色到顶（纯蓝的天、纯红的灯）不算：它在直方图那个颜色的右边缘看得到，照片上没有"白到没层次"的地方。红色的车不会因为红色通道是 255 就被当成过曝。
- **三角亮起的门槛：溢出的点占取样点的 0.5% 以上**（`WARN_SHARE = 0.005`，1/200）。更少的点多半是几粒噪点或一颗高光，不值得提醒。没到门槛时三角是灰的，鼠标停上去的提示里写着实际占比。
- **点三角**：只在照片上标那一边（左三角标蓝，右三角标红），再点关掉。**按 J**（和 Lightroom 一样）：任何一边开着就全关，否则两边都开。
  标出时照片左下角有一条说明（蓝 = 死黑，红 = 死白）；对应的点是 0 个时写"没有死黑的点 / 没有死白的点"。
- 溢出提示的开关在这次打开页面期间一直记着，换照片不丢；刷新页面后默认关。
- 按住空格看原图时不标；左右对比时只在右半边（编辑后）标。
- 滑块有焦点时 J 也有用（拖完曝光马上按 J 是最常见的用法）。`histogram.js` 自己监听 J，滑块、开关、按钮不吃字母键，只有文本输入框和下拉框里不响应。

## 怎么数

规则只有一份，写在 `histogram_math.js`，显卡着色器、引擎里的拷贝和 numpy 参考实现都和它逐个核对（`tests/test_histogram.py`、`tests/test_histogram_gpu.py`）：

- 亮度 = `(2126·R + 7152·G + 722·B + 5000) // 10000`（Rec.709 权重的整数运算）。
- 取样：矩形里横竖每隔 `stride` 个像素取一个。`stride` 是让取到的点不超过 262144 个（512 × 512）的最小整数，小图就是 1，即逐个像素数。
- 结果是 1026 个计数：红、绿、蓝、亮度各 256 档，后面两个是死黑、死白的点数。

### 显卡路径（`gpu_preview` 开着、这张照片走显卡时）

- 引擎在**成片纹理**（颜色、几何之后的 1:1 纹理，也就是屏幕上这一帧）上数：一个 compute 通道，8 × 8 个工作组，每组先在组内数一份再并进全局。几十万个点，不到一毫秒。
- 异步读回（4 KB）。上一次还没读完，这一轮直接跳过（`Engine.histogram()` 返回 `null`），**不排队、不等待**；画面还有一帧没画出来（`Engine.pending`）时也不数，等它画完。数的通道排在已经提交的画面之后，不会拖慢预览。
- 溢出提示是 `present.wgsl` 里的一个选项（`Engine.setClipOverlay`）：显示那一遍把死黑的点盖成蓝、死白的点盖成红，判定和颜色与上表相同。只重画最后一遍，不重算颜色。缩小显示时按缩小后的颜色判断，看到的是显示分辨率上的结果。

### 服务器出图的退路（显卡预览关着、浏览器没有 WebGPU、透视 / 畸变、只有 JPG 却选了配方等）

- 把服务器出的那张 JPEG 用 `createImageBitmap` 解码（不做色彩转换），降到长边 384 再数。解码在浏览器的解码线程里，数 10 万个点不到一毫秒，没有另开 worker。
- 画面带边框或时间戳时，另要一张没有它们的小图来数（`/render` 的请求体里 `frame: none`、`stamp: 关`，长边 800），因为边框的颜色不该算进直方图。
- 溢出提示画在叠在照片上的一块 canvas 里（长边 800）。**带边框时不标位置**（边框改变了画面的尺寸和位置，小图对不上；左下角会说明），直方图不受影响；只有时间戳时照常标。
- 更新的快慢跟着服务器出图：拖滑块时每 120 毫秒请求一次，所以通常比显卡路径慢。

### 更新节奏

`histogram.js` 每 50 毫秒看一眼有没有变化（引擎的成片纹理换了版本 `Engine.contentVersion`、服务器图换了、裁剪框动了），变了才数，所以最快每秒 20 次；页面在后台时不数。数的过程中又变了，等这一次结束再数最新的。

## 裁剪页

裁剪页的画面是整张未裁切的照片。直方图**只数裁剪框里面的**，也就是将要导出的部分；拖框、换比例时它跟着变。
溢出提示仍然标在整张照片上（你要看的是哪里会死黑 / 死白，包括框外面）。左下角的"没有死黑的点"只在整幅时才写，裁剪页里只写颜色说明，不下"没有"的结论。
离开裁剪页回到整幅。

## 已知的限制

- 服务器路径的更新速度受服务器出图限制（见上）；带边框时没有位置提示。
- 显卡路径的溢出提示按显示分辨率判断：缩小很多时，一个显示像素里混着死白和别的点，平均后可能不够 253，所以细小的死白点在缩小的画面上可能看不到。放大到 100%（Z）可以看到每个点。
- 直方图描述的是 8 位 sRGB 码值（导出的 JPG 里的值），不是 RAW 的线性数据。
- 取样不是平均而是隔点取：大图上每个点有 0.2% 左右的统计误差，对 0.5% 的门槛来说远远够了；小图（≤ 512 × 512）是逐个像素精确数的。
