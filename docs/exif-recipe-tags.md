# 照片里的拍摄配方

信息面板的「拍摄配方」读取照片 EXIF Copyright（33432）中的 `GXR1` 标签。它与「电脑编辑」中的配方各自独立。

```text
GXR1 <10 位十六进制目录身份> <28|50|MT> <01–99> <10 字符旋钮>
```

旋钮字段固定 10 个字符，`0–9A–I` 对应整数 0–18。强度用整数乘 10%，范围 0–150%；其余旋钮用整数减 9，范围 −9 到 +9。`-` 表示该项不可调，不是零。只有前四项的旧记录表示「微调未知」，预测使用目录默认值。短名和末尾星号不属于新格式。

标签最多 47 个 ASCII 字节，含一个结尾 NUL。Pillow 已去掉 NUL 的字符串按最多 46 个字节解析；缺少 NUL 的有界字节也按相同规则处理。非 ASCII、内嵌 NUL、控制字符、错误旋钮字母或长度、超长值都不算配方标签。

`camdata/recipe_tags.py` 的 `KNOB_ORDER` 集中登记顺序。已对照 2026-11-10 的相机侧 `research/build_g179_exif_r2/REPORT.md`，与 Studio 控件表及 g178 菜单一致：强度、对比度、高光、阴影、褪色、饱和度、色温、色调、分离色调、黑白滤镜。报告样品 `9999C9999-` 表示强度 90%、褪色 +3，黑白滤镜不可调。后续格式或顺序变更时递增 `RECIPE_TAG_VERSION`，索引用已缓存的 Copyright 重解码。

`camdata/catalog_names.py` 只登记封存目录的名字，不含配方数据。g176 的目录身份是 `d25d2f0a68`，g178 是 `6a3a5a3c02`。查名必须同时匹配身份、单元和相机列表位置。单元代码 `28`、`50`、`MT` 分别对应 `qlaunch`、`jlaunch`、`l08firm`。查名不依赖当前导入的相机数据。

已知目录显示登记名称及调过的项，名称沿用配方面板。未知目录或目录中不存在的位置显示标签前四项及「相机记录，Studio 目录里没有」，不借用其它代或单元的名称。普通版权文字和坏标签原样显示为「版权」，配方显示「未标记」。

有 RAW 且没有用户配方选择时，编辑器沿用相机记录的配方和旋钮，预测及 LUT 基准共用同一份选择。必须导入对应的封存目录，缺失或错配时拒绝冒用当前目录的同位置配方。目录不支持的数值也不钳位或改为默认。用户后来选择的配方优先；显式关闭存为 `recipe: null`，缺键才表示沿用拍摄记录。只有 JPG 的照片显示相机 JPG，不把拍摄旋钮丢掉后生成默认参数的近似预测。

JPEG 和 DNG 都沿现有元数据读取路径解析，导入、补全和重建将版权文字及解析结构保存到 SQLite。`GET /api/photos` 和 `GET /api/photos/{id}` 从索引返回 `copyright` 与 `recipe_tag`，不会为了配方标签再打开照片。RAW 与 JPG 配对时优先用 JPG 的 Copyright，JPG 没有该字段才用 DNG；补全照片遵守相同顺序。

旧索引只添加空列，不丢掉原来的照片、导入证明或编辑记录，也不自动扫描照片。升级前已导入的照片需要重建索引后才显示标签。JPEG、RAW 中性转换、编辑成片及精简 EXIF 的导出路径都保留源照片的 Copyright，不按目录名改写标签。

`tests/test_recipe_tags.py` 在临时目录生成 JPEG 和带 CFA 的 DNG，验证解析、索引、补全、界面文案及 JPEG 和 PNG 导出。`tests/test_recipe_tag_render.py` 用独立合成目录、CFA 和校准核对预测像素、LUT 基准、用户覆盖及显式关闭。可选的本地封存库对照覆盖登记位置和实际旋钮条目；缺少研究副本时明确跳过。
