# 照片里的拍摄配方

信息面板的「拍摄配方」读取照片 EXIF Copyright（33432）中的 `GXR1` 标签。它与「电脑编辑」中的配方各自独立。

```text
GXR1 <10 位十六进制目录身份> <28|50|MT> <01–99> [短名][ *]
```

短名可以截短或缺失，末尾 ` *` 表示已微调。标签最多 47 个 ASCII 字节，含一个结尾 NUL。Pillow 已去掉 NUL 的字符串按最多 46 个字节解析；缺少 NUL 的有界字节也按相同规则处理。非 ASCII、内嵌 NUL、控制字符、超长值和格式错误不算配方标签。

`camdata/catalog_names.py` 只登记封存目录的名字，不含配方数据。g176 的目录身份是 `d25d2f0a68`，g178 是 `6a3a5a3c02`。查名必须同时匹配身份、单元和相机列表位置。单元代码 `28`、`50`、`MT` 分别对应 `qlaunch`、`jlaunch`、`l08firm`。查名不依赖当前导入的相机数据。

已知目录使用登记名称，忽略照片中的短名。未知目录退回相机短名并显示「相机记录，Studio 目录里没有」；短名缺失时显示标签前四项。已知目录中不存在的位置也显示前四项，不借用其它代或单元的名称。普通版权文字和坏标签原样显示为「版权」，配方显示「未标记」。

JPEG 和 DNG 都沿现有元数据读取路径解析，导入、补全和重建将版权文字及解析结构保存到 SQLite。`GET /api/photos` 和 `GET /api/photos/{id}` 从索引返回 `copyright` 与 `recipe_tag`，不会为了配方标签再打开照片。RAW 与 JPG 配对时优先用 JPG 的 Copyright，JPG 没有该字段才用 DNG；补全照片遵守相同顺序。

旧索引只添加空列，不丢掉原来的照片、导入证明或编辑记录，也不自动扫描照片。升级前已导入的照片需要重建索引后才显示标签。JPEG、RAW 中性转换、编辑成片及精简 EXIF 的导出路径都保留源照片的 Copyright，不按目录名改写标签。

`tests/test_recipe_tags.py` 在临时目录生成 JPEG 和带 CFA 的 DNG，验证解析、索引、补全、界面文案及 JPEG 和 PNG 导出。可选的本地封存库对照覆盖所有登记位置；缺少研究副本时明确跳过。
